# Локальный контур — отличия от VPS

Как запускать, что отличается от серверного компоуза и **почему**. Правило
OPS-02: локальный контур, тихо разошедшийся с боевым, хуже отсутствующего —
поэтому каждое отличие здесь записано с причиной, а не просто сделано.

Источник истины по составу контура — `../../site-platform/deploy/vps/docker-compose.yml`.
Здесь только надстройка.

## Запуск

```bash
cd deploy/local
docker compose -p broker-local \
  --project-directory . \
  -f ../../site-platform/deploy/vps/docker-compose.yml \
  -f docker-compose.local.yml \
  up -d --build
```

`--project-directory .` обязателен. Без него compose разрешает относительные
пути от папки первого `-f`-файла, то есть от `site-platform/deploy/vps/`, и все
контексты сборки уезжают в несуществующие каталоги.

**После подъёма с нуля (или если том `broker-local_bus-data` пересоздан):**

```bash
bash bus-setup.sh      # кредлы, права и топология шины
```

Свежий RabbitMQ поднимается с `RABBITMQ_DEFAULT_USER=site-web`, а такой
пользователь получает тег `administrator` и права `.*` на всё. Без этого шага
продюсер умеет читать чужие очереди и переписывать права себе, и **ни одной
ошибки в логах при этом не будет** — вся работа BUS-01 и OPS-13 снимется
молча. Скрипт идемпотентен и печатает права до и после.

**После пересборки `web` вебхук инвалидации больше дёргать не нужно** —
обход снят 19.10, и это не «забыли написать». `B-OPS-005`: граница доступа
вычислялась на сборке и замерзала в образе, витрина до часа после выкатки
показывала ложное «список недоступен» вместо «инструменты пока не выбраны».
`WEB-07` убрал вопрос к границе из серверного рендера в островок
`TickerGate` + ручку `GET /api/tenant/access`; диагноз считается из окружения
контейнера в рантайме. Проверено на пересборке 19.10: сразу после подъёма, без
единого вебхука, ручка отдаёт `state: "empty"`, а `/ru/instruments` —
`data-access-state="empty"` и текст «Инструменты пока не выбраны».

Инструкция оставлена строкой, а не удалена: выкаченный обход, про который
забыли, что он больше не нужен, живёт дольше самого дефекта.

## Карта портов — занято явно, не по умолчанию

| Сервис | В контейнере | На хосте | Почему не как на VPS |
| --- | --- | --- | --- |
| web | 3000 | **3100** | 3000-3005 заняты dev-серверами соседей |
| cms | 3001 | **3101** | 3001 занят `next start` команды site-platform (PID 33264) |
| cabinet | 3002 | **3102** | тот же диапазон |
| mds | 3003 | **3103** | 3003 занимал `tsx src/index.ts` команды mds |
| шина AMQP | 5672 | 5672 | свободен |
| шина, консоль | 15672 | 15672 | свободен |
| site-db, cms-db | 5432 | не публикуются | как на VPS: только внутри сети compose |

**Почему целый блок 3100-3103, а не «свободные по одному».** Замер показал, что
хостовые dev-серверы дрейфуют: `next` ушёл с 3000 на 3001, затем появился
второй экземпляр на 3005. Контур, занимающий спорный диапазон, однажды
поднимется не там, где записано, и это обнаружится не сразу. Блок 3100+ пуст
целиком и никем не используется.

Занято на 03.09 чужими: 8888 — терминал; 5433, 5673, 15673, 6380, 9000, 9001 —
`broker-cms-dev`; 3030, 4000, 5434, 6381, 8090 — `aihub`.

## Отличия от VPS-компоуза, по одному

### 1. Контексты сборки — другие имена папок

На сервере рядом с `deploy/` лежали `Sait_Platform`, `Broker_CMS`, `Broker_MDS`.
Здесь — `site-platform`, `cms-legacy`, `mds`. Переопределены все шесть
контекстов сборки и монтирование `db/init` у `site-db`.

Базовый компоуз не трогали: его пути верны для серверной раскладки, и менять их
под локальную машину значило бы ломать их для сервера.

### 2. `Broker_CMS` — это `cms-legacy`, а не `cms`

Самое важное отличие. В папке `cms/` лежит **CMS v2**: у неё нет Dockerfile
вообще, другая база (`broker_cms_v2` против `broker_cms`), другие зависимости
(redis, minio) и другой способ запуска — команда cms поднимает приложение на
машине, а в Docker держит только инфраструктуру.

Базовый компоуз описывает **старую** CMS: `pnpm payload migrate`, `pnpm seed`,
стадия `AS build` для `cms-migrate`. Всё это есть в `cms-legacy/` и совпадает
построчно. Поэтому контур поднимается с `cms-legacy`.

**Это не решение о том, какая CMS правильная.** Это констатация: сегодня
контейнеризована только legacy. Вопрос «когда контур переезжает на v2» — к
штабу и команде cms, он тянет за собой новый Dockerfile, имя базы и две новые
зависимости в компоузе. Подменять одно на другое молча было бы ровно тем
расхождением, которого OPS-02 велит избегать.

### 3. Порты 3100-3103

См. карту выше.

Технически: в надстройке у портов стоит тег `!override`. Без него compose
**добавляет** порт к базовому списку, а не заменяет — проверено `config`:
получалось `3000,3100`, и контур занял бы оба, включая спорный 3001, который
уже занят чужим процессом. Ошибка была бы обнаружена только при падении
`up`, а при неудачном стечении — не обнаружена вовсе.

### 4. Шина поднимается здесь

На сервере RabbitMQ — чужая общая инфраструктура (`/opt/platform-bus`), в
компоузе контура её нет. Локально её взять негде, поэтому сервис `bus` добавлен
в надстройку.

Пользователь `site-web`, vhost `platform` — заводятся самим контейнером через
`RABBITMQ_DEFAULT_*`. **Права сейчас широкие, и это намеренно:** BUS-01 требует
сначала воспроизвести `403 ACCESS_REFUSED`, а воспроизводить нечего, если права
сузить заранее. Сужение — задача BUS-01.

Healthcheck — `rabbitmq-diagnostics check_running`, а не `ping`. `ping`
отвечает «жив», пока жив процесс Erlang, даже если брокер не принимает
соединений: это проверка, которая проходит при сломанном сервисе.

### 5. GlitchTip не поднимается

OPS-09 отложена осознанно. `SENTRY_DSN_WEB` и `SENTRY_DSN_BFF` пустые — SDK при
пустом DSN молчит и не мешает работе. Следствие: ошибки контура локально видны
только в логах контейнеров.

### 6. Пустые ключи там, где нужен внешний доступ

- `TWELVEDATA_API_KEY` пуст — вселенная MDS будет только Binance. Для проверки
  «сервис поднялся и отвечает» этого достаточно, для проверки форекса и
  металлов — нет.
- `SSO_PRIVATE_KEY_B64` пуст — кабинет поднимается, но выдача SSO-токенов
  терминалу не проверяется.

Оба — сознательные ограничения объёма, а не упущения. Если понадобится
проверять эти сценарии, ключи придётся завести.

### 7. `VPS_HOST=localhost`

Публичный IP сервера заменён на `localhost`: он подставляется в ссылки, которые
открывает браузер, и в `FRAME_ANCESTORS`.

## Секреты

`.env` рядом — сгенерирован локально, одноразовый, только для этой машины.
Закрыт `deploy/.gitignore` (`.env`, `.env.*`). В историю попадать не должен
никогда.
