# Сервер: что где лежит и почему

Раскладка на машине повторяет этот каталог один в один:
`/srv/broker/<служба>/`. **Файлы здесь — источник правды**, на сервере их
копия. Правка, сделанная только на машине, для соседей не существует: у этого
правила есть цена, уже заплаченная (Р-121).

```
/srv/broker/
  proxy/     Caddy: единственное, что смотрит наружу (80, 443)
  terminal/  шлюз + фронт + своя база
  bus/       RabbitMQ: обменники, DLQ, кредлы приложений
  cache/     Redis
```

## Что лежит на машине и НЕ лежит здесь

**`.env` каждой службы.** Права `600`, владелец `root`. Пароли сгенерированы
на месте и нигде не переиспользованы: пароли контура лежали в репозиториях и
потому считаются скомпрометированными. Рядом с каждым `.env` — свой
`.env.example` без значений, он и показывает состав.

Хранилища секретов у нас нет, и это **открытая строка реестра готовности**,
а не решённый вопрос. Файл с правами 600 — не хранилище секретов, это
отсрочка с названной ценой: ротации нет, журнала доступа нет, кто читал —
неизвестно.

## Две внешние сети, и они разные по смыслу

| Сеть | Кто в ней | Зачем |
| --- | --- | --- |
| `broker-edge` | прокси и то, что он проксирует | единственный путь снаружи внутрь |
| `broker-back` | общая инфраструктура (шина, кеш) и её будущие клиенты | службы находят друг друга по имени |

Обе **внешние** и заводятся до подъёма стеков:

```sh
docker network create broker-edge
docker network create broker-back
```

Если бы каждый стек создавал свою — соседи не видели бы друг друга, а
`reverse_proxy` в Caddy молча отвечал бы 502.

## Портов наружу не публикует НИКТО, кроме прокси

Ни одного `ports:` в стеках приложений. Заслон
`/etc/broker/docker-firewall.sh` это и так перехватил бы — Docker обходит
обычный брандмауэр, и заслон фильтрует по исходному порту через conntrack, —
но полагаться на заслон вместо правильной настройки значит полагаться на
прочитанную записку.

## Домена и адреса машины в этом репозитории нет

И это не забывчивость. Репозиторий **публичный**, а связку «адрес живой
машины плюс описание того, что на ней ценного или слабого» мы не публикуем
(Р-012). Домен живёт в одном месте — `/srv/broker/proxy/.env` на машине, —
и оттуда его читают Caddy и человек.

Поэтому в документах зоны имена пишутся как `<имя терминала>`, а не
подставляются. Поймано на себе 23.10: домен уже был вписан в `ЗАДАЧИ.md`
рядом с перечнем того, чего на машине нет.

## Как выкатывать

Сборки на сервере нет и быть не должно: образы приходят из `ghcr.io` по
**хешу коммита** (OPS-23). Выкатка новой ревизии — это правка одной строки
`image:` и `docker compose up -d`.

```sh
cd /srv/broker/<служба> && docker compose pull && docker compose up -d
docker compose ps        # состав, а не «вроде поднялось»
```

**Состав проверяется перечислением.** Служба, которая не стартовала,
в выводе выглядит почти так же, как та, которой в описании нет вовсе.

## Чего на машине нет

- **Витрины и кабинета** — их образы собраны с адресами для разработки,
  ссылки входа повели бы в никуда. Ждут `WEB-22`.
- **CMS** — у v2 нет Dockerfile, развернуть нечего.
- **MDS** — репозиторий на заблокированном аккаунте, образа не существует.
- **Хранилища секретов, мониторинга молчания** — открытые строки реестра.
