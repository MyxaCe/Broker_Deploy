# Схема витрины и кабинета — ВТОРАЯ КОПИЯ, и это долг

Файлы `*.sql` скопированы из `Sait_Platform/db/init` на коммите

    d03ceca85df8b4fbca0beaf0a171f47fbd574767

Postgres выполняет их **ровно один раз**, при создании пустого тома
(`docker-entrypoint-initdb.d`). На существующем томе они не исполняются
вовсе — значит обновление схемы этим путём НЕ едет.

**Почему копия, а не ссылка.** На сервере нет клона `Sait_Platform`, и
заводить его значило бы вернуть сборку на сервере через заднюю дверь.

**Чем это плохо и когда возвращаться.** Два места с одной схемой
расходятся молча: правка в `Sait_Platform/db/init` сюда не доедет, а
заметим мы это на следующем пустом томе — то есть при восстановлении из
бэкапа, в худший момент. **Возвращаться:** когда у витрины появится
настоящий прогон миграций (не initdb) либо когда схему поменяют первый
раз. **Цена промедления:** восстановление на схеме, отставшей от кода.

Сверить копию с источником:

    diff -r <клон Sait_Platform>/db/init ./ --exclude README.md
